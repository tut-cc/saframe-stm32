# 0006: 安全化済みフレームだけをLCDへ公開する

Status: accepted (2026-09-22)

DCMIPPのカメラ出力は非公開のRGB565作業バッファへsnapshot取得し、物体検出後の
MASKまたはMOSAIC処理が完了したフレームだけをLTDCへ公開する。LTDCが参照する表示
バッファとDCMIPPが書き込む作業バッファを分離し、RAW状態のバッファはLTDCへ設定
しない。

処理期限は、DCMIPP Pipe 1（LCD用画像）とPipe 2（NN入力）の両snapshot完了から
安全化処理完了までの33 msとする。期限内ならVBlankで背景アドレスを切り替え、期限
超過ならそのフレームを破棄して直前の安全化済みフレームを保持する。起動直後、モデル
重み不正時、最初の処理完了前は黒背景を維持する。

## Context

配信用カメラでは、検出や描画が遅れたときに未加工映像へフォールバックすると、隠す
べき対象が一瞬でも公開される。従来構成はDCMIPP Pipe 1をLTDCの背景バッファへ連続
出力し、ARGB4444前景レイヤにマスクを描いていたため、前景更新より先にRAWフレーム
が表示される可能性があった。

この段階では処理能力の最適化より公開境界の安全性と実測を優先する。ST-YOLOX 480を
維持し、`capture_ms`、`inference_ms`、`postprocess_ms`、`render_ms`、`total_ms`、
公開数、期限超過破棄数、連続破棄数をT-Monitorコンソールへ出力する。33 msを満たせ
ないこと自体は許容し、その測定結果を320/416モデル選定に使う。

## Considered Options

- ARGB4444前景レイヤだけで隠す: 実装は軽いが、背景と前景の更新は不可分ではなく、
  RAWフレームの一時表示を構造的に禁止できない。
- 期限超過時に黒画面へ切り替える: 安全ではあるが映像が頻繁に点滅し得るため、最後の
  安全化済みフレームを保持する。
- 期限超過でも遅れて公開する: 映像の更新数は増えるが、30 fps相当の鮮度要件を満たさ
  ないフレームが表示され、負荷不足を観測しにくくなるため採用しない。
- 先に320/416モデルへ変更する: 速度改善と公開ゲート導入を同時に行うと効果の原因を
  分離しにくいため、ST-YOLOX 480のままゲートを検証する。

## Consequences

- フレーム状態は`WORKING → PROCESSED → PUBLISHED`または
  `WORKING → PROCESSED → DROPPED`だけを許可する。
- VisionタスクはRenderタスクが公開または破棄を確定するまで作業バッファを再利用
  しない。公開時はLTDCのVBlankリロード完了を待ってから旧表示バッファを再利用する。
- センサー起動直後はPipe 1だけで非公開バッファへ1枚snapshot取得して破棄し、カメラ
  のストリーム開始を確認してからPipe 1とPipe 2の同時snapshot待ちへ移る。
- MASKはRGB565画素を黒化し、MOSAICは同じ非公開バッファ内でRGB565各成分の
  ブロック平均を計算する。ARGB4444前景レイヤは状態表示専用とする。
- カメラタイムアウト時は最後の安全化済みフレームを保持し、前景レイヤにエラーを表示
  する。
- RGB565背景バッファが2面必要になり、PSRAM使用量が768,000 byte増える。
- 現在の対象はSTM32N6570-DKのLCD 800×480のみ。HD 1280×720、letterbox、USB
  UVC、独自クラスモデルは後続マイルストーンとする。

## Verification

- ホスト試験でMASK、MOSAICのブロック平均、境界クリップ、複数ROI、ゼロ検出、
  32/33/34 msの公開判定を検証する。
- `PRIVACY_TEST_RENDER_DELAY_MS=40`を定義すると期限超過を意図的に発生できる。
- 実機では起動時の黒背景、VBlankでの公開、期限超過時の背景アドレス維持、および
  ST-YOLOX 480で1000フレーム以上の計測を確認する。
